# 安装与使用

目标：同一段提示词，交给 Opus 5.5 和交给 DeepSeek，做出的动效视频基本一样。
风格由提示词决定，skill 不预设风格。

## 安装

- 把整个 `motion-design-prompt-generator` 文件夹放进 skills 目录。
- 只能装单个文件的平台，只装 `SKILL.md` 也能用：里面有工具函数的接口说明。起步项目的完整代码放在 `REFERENCE.md`，需要时再看。

## 一次性准备（电脑上）

1. 安装 Node.js 22 以上版本，以及 ffmpeg（自查脚本要用）。
2. 复制 `templates/remotion-starter` 文件夹，作为你的项目文件夹。
3. 在这个文件夹里运行：

   ```bash
   npm install
   ```

   如果提示 esbuild 需要批准，再运行：

   ```bash
   npm approve-scripts esbuild && npm rebuild esbuild
   ```

## 每次做视频

**每做一个新片子，务必新开一个 DeepSeek 对话。** 在老对话里，它容易沿用上一版代码，新规则就用不上。

1. 在 DeepSeek 里直接发提示词，内容和发给 Opus 的一模一样。
2. 它会回复：解读、三张清单（需求、变形、元素）和时间线、代码文件、配乐 `scripts/cues.json`、核对表、五项评分。
3. 把文件放进项目文件夹的对应位置。
4. 运行下面的命令预览。它会先根据 `cues.json` 生成配乐：

   ```bash
   npm run studio
   ```

5. 导出 `out/film.mp4`：

   ```bash
   npm run render
   ```

6. 想快点看效果：`npm run preview` 导出半分辨率小样，不用改任何设置。
7. 自查：

   ```bash
   npm run check
   ```

   它会检查格式、第 0 帧底色、循环接缝和声音，在 `out/check/` 生成缩略图、关键帧和音频频谱图，并打印运动曲线。凡是报 FAIL 的地方，都截图发给它修。
8. 有问题就截图发给它，说“评审修复”。

其他说法：
- 只想要扩写后的提示词，就说“只要提示词”。
- 回复被截断，就说“继续”。

## 这个 skill 怎么保证“任何需求都做得好”

它不针对某个题材，而是把 Opus 默默做的事变成固定流程：

1. **优先级**：提示词原话 > 画面和美术质量 > 连贯 > 节奏和声音 > 记录工作。
2. **三张清单**：需求清单（每个数值）、变形清单（谁变成谁）、元素清单（每个要画的东西、它的结构、尺寸和位置）。
3. **从提示词推导风格**：提示词写了风格就照做；只给了感觉，就从风格种子改起；只有一句话创意，就按“题材 → 世界、情绪 → 能量、具体数值、排除模板感”四步，现场写一份新的风格规范。
4. **按元素类型做**：任何需求都可以拆成这 9 类，每类都写了怎么构建、怎么动、常见错误：
   - 文字、物体、角色、场景环境、数据图表、界面和产品、转场、质感和光、声音。
5. **工具只管机制**：位置、变形、材质、骨架、配乐、自查都有测试过的工具，但长什么样永远由这部片子自己设计。
6. **五人评审**：需求、连贯、节奏和声音、设计、工艺，每项 8 分以上才交付。

## 包里有什么

| 路径 | 用途 |
| --- | --- |
| `SKILL.md` | 优先级、7 个阶段、9 类元素的做法、通用规则、工具接口说明（约 24 KB） |
| `design-systems/` | 7 个风格种子，只在提示词没写风格时作为起点 |
| `templates/remotion-starter/` | 测试过的 Remotion 项目，含动效工具、配乐合成器 `score.mjs`（12 种音色）、自查脚本 `check.sh` |
| `examples/drafting-table/` | 一种风格的演示，不是默认风格 |
| `REFERENCE.md` | 起步项目全部源码，只在需要时查看 |
| `examples/character-rig/` | 角色骨架示例：同一套骨架做出两个完全不同的角色，只演示机制，不是角色模板 |
